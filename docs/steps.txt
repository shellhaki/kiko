KIKO — BUILD CHECKLIST
Created: November 8, 2026

PURPOSE AND TRACKING

This is the working checklist for building Kiko as a free, open-source
desktop app. Creating this plan does not start implementation.

[ ] = not finished
[x] = done

Work in the order below. Tick a step [x] only when its deliverables and
checks are complete. Record its completion date and a short evidence note
under that step (what works and which checks passed). Partial work stays
unchecked; record what remains. Never mark an implementation step done
because only its UI mockup, scaffold, or happy path exists. If later work
breaks a completed step, reopen it and note the regression.

For every implementation step:
- Follow root agents.md: clean code, standard folders, clear identifiers,
  minimal necessary comments, and no unnecessary abstractions.
- Add and run meaningful tests for each functionality, including relevant
  failure cases. Use deterministic provider fixtures for routine tests;
  keep real API checks explicit and separate from ordinary test runs.
- Run relevant Go tests, frontend tests, type checks, and build checks for
  the changed layers. Check visible screens against the references.
- Update relevant docs and this file before reporting completion.
- Never commit API keys, local databases, personal data, or build output.

SOURCE DOCUMENTS

- agents.md: repository working rules.
- docs/kiko-spec.md: architecture, tool contract, and release scope.
- docs/design-system.md: colors, fonts, icons, and styling.
- docs/folder-workspaces.md: current folder roots, file tools, permissions,
  startup timing, and motion contract (November 9 owner revision).
- docs/references/screens/README.md: supplied layouts and startup flow.
- docs/kiko-pitch.md: audience and longer-term product direction.

The example screens supply layout. The Codex reference and design system
supply visual styling. Future features described in the pitch do not
automatically enter v0.1.
